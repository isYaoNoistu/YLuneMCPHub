# 配置与数据落在哪里

月弦是一套网关方法论：**运行配置全部进 PostgreSQL**。换机器、升级、容灾，把库迁走就齐了。不要把服务器、用户、分组、Key、系统设置写在仓库里的 JSON 里。

| 东西 | 放哪 | 不要放哪 |
| --- | --- | --- |
| 服务器、分组、用户、Bearer Key、系统设置、内置提示词 / 资源 | Postgres（`servers`、`groups`、`users`、`bearer_keys`、`system_config` 等表） | 仓库里的 `mcp_settings.json`、镜像层、git |
| 上游 Token、库口令、夜莺 / Jenkins 地址 | 进程环境变量或 `${ENV}` 引用；值在运行环境 | 提交到 git 的任何文件 |
| 管理员首次口令 | `ADMIN_PASSWORD`（只在库里还没有管理员时用一次） | 文档、截图、compose 默认值 |
| 向量索引（智能路由） | 同一套 Postgres（pgvector） | 单独再备一份 JSON |

`mcp_settings.json` 在仓库里只是**空种子**（没有用户、没有服务器）。本机 `pnpm backend:dev` 没有 `DB_URL` 时，才会用 `data/mcp_settings.dev.json` 凑合跑界面，这份在 `data/` 里，不进 git。`NODE_ENV=production`（以及未设成 development/test 的启动）没有 `DB_URL` 会直接退出。

## 日常怎么改配置

打开控制台改。写的是库，不是磁盘上的 JSON。

环境变量只解决「进程怎么连库、首次管理员口令、上游 `${TOKEN}`」。不要指望改完 JSON 热更新生产。

## 迁走 / 备份

```bash
# 在 deploy/ 目录
docker compose exec -T postgres pg_dump -U ylune ylune > ylune.sql
```

恢复：

```bash
docker compose exec -T postgres psql -U ylune -d ylune < ylune.sql
```

控制台「导出配置」得到的 JSON 是**当时库内容的快照**，给人看或应急，不是运行时存储。真正搬家用 `pg_dump`。

## 手里还有一份旧 JSON 时

只在**空库**上做一次导入，成功后删文件、去掉环境变量：

```bash
# 本机已有 Postgres，库是空的
set YLUNE_IMPORT_SETTINGS_FILE=data/mcp_settings.local.json
set DB_URL=postgresql://ylune:...@127.0.0.1:5432/ylune
pnpm backend:dev
```

导入完成后：

1. 控制台核对服务器 / 用户 / 组是否都在。
2. 关掉 `YLUNE_IMPORT_SETTINGS_FILE`。
3. 删除那份 JSON（至少不要留在仓库根目录）。

空库且不设这个变量时，**不会**再自动读 `mcp_settings.json` 灌库，避免一份脏文件被带进镜像或工作目录后把密钥写进库。

## Docker

[deploy/README.md](../deploy/README.md) 只挂 Postgres 卷。月弦容器不写 `mcp_settings.json`。构建时 `.dockerignore` 会排除本地 JSON 和 `data/`，避免把本机配置打进镜像。

Linux 上 `/data/DevOpsMCP` + `/data/YLuneMCPHub`、把二进制挂进容器：见 [Linux部署.md](Linux部署.md)。挂载点默认 `/data/ylune-mcp`（二进制、targets、pgpass），不要提交进任何一个仓。
