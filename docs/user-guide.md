# 月弦使用教程

本文按控制台真实表单写：每一项填什么、什么时候留空、填错会怎样。产品介绍和和 [DevOpsMCP](https://github.com/isYaoNoistu/DevOpsMCP) 的关系见仓库根目录 [README.md](../README.md)。

仓库和文档里不要写真实 Token、密码、内网地址。示例一律用占位符。

---

## 1. 先搞清三件事

1. **月弦是网关**，不是夜莺 / Jenkins / PostgreSQL 客户端。那些只读工具在 DevOpsMCP。
2. **三个词不要混：** **控制台账号**用密码登录后台；**Access Key** 是智能体调 `/mcp` 的 Bearer；**Credential** 是凭据中心加密保存的自定义键值包，既不是登录密码，也不是 Access Key。
3. **普通用户能调什么，只看这个用户勾了哪些 MCP 和工具。** 服务标成「公开」不会单独放开 MCP 调用。管理员默认全部已启用服务，不必再勾。运行配置在 PostgreSQL，不在仓库 JSON。详见 [config-and-data.md](config-and-data.md)。

建议顺序：启动 → 管理员改密码 → 加服务器 → 建 MCP 用户并勾工具 → 在用户页复制 JSON 或 TOML 交给智能体。需要存只读库口令时再打开凭据中心。随时可以再复制。

## 2. 安装与启动

### 2.1 本机开发（推荐先这样验收）

需要 Node 20+、pnpm。

```bash
git clone https://github.com/isYaoNoistu/YLuneMCPHub.git
cd YLuneMCPHub
pnpm install
```

开两个终端：

```bash
pnpm backend:dev
pnpm frontend:dev
```


| 项        | 填什么 / 打开哪里              | 说明                                      |
| -------- | ------------------------ | --------------------------------------- |
| 控制台      | http://127.0.0.1:5173    | Vite 前端，API 会代理到 3000                   |
| MCP 端点   | http://127.0.0.1:3000/mcp | 智能体连这个，不要连 5173                        |
| 开发账号     | `admin` / `admin123`     | 仅本机。登录后立刻改密码                            |
| 可写配置     | 有 `DB_URL` 时进 Postgres；否则才是 `data/mcp_settings.dev.json` | 不要把 JSON 提交进 git                          |


只开前端、后端没起来时，页面会一直转或登录失败。先看跑 `backend:dev` 的那个终端有没有报错。

本机不要同时再开一份不带热更新的 `tsx src/index.ts`，两份都会抢 3000，智能体连上的可能是旧进程。

### 2.2 生产式启动（编好再跑）

```bash
pnpm build
pnpm start
```

此时前后端都在 3000。必须先设 `DB_URL`（以及 `ADMIN_PASSWORD`），否则进程会退出。不要用开发默认密码。

### 2.3 Docker

整套编排在 [deploy/](../deploy/README.md)：Postgres（pgvector）+ 现场构建的月弦镜像，可选 Nginx。仓库根目录不再放 `docker-compose.yml` / `docker-compose.db.yml`。

**只起月弦、暂不接 DevOpsMCP：**

```bash
cd deploy
cp .env.example .env   # Windows：Copy-Item .env.example .env
# 编辑 .env：至少改 ADMIN_PASSWORD、DB_PASSWORD
docker compose up -d --build
```

**Linux 上两仓都在 `/data`：** 月弦仍是上面这一条 `docker compose up`（容器挂载点 `/opt/mcp`）。编译、灌文件、自动注册到控制台：到 DevOpsMCP 跑 `deploy/attach.sh`。见 [linux-deploy.md](linux-deploy.md) 和 [DevOpsMCP deploy](https://github.com/isYaoNoistu/DevOpsMCP/blob/main/deploy/README.md)。

| 环境变量 | 示例 | 说明 |
| --- | --- | --- |
| `YLUNE_PORT` | `3000` | 宿主机映射端口 |
| `ADMIN_PASSWORD` | 自己设的强密码 | 仅首次创建管理员；不要用 `admin123` 对内发布 |
| `DB_PASSWORD` | 自己设 | 容器内 Postgres 口令，请用字母数字 |
| `MCP_MOUNT_DIR` | `/data/ylune-mcp` | 宿主机挂载点，对应容器 `/opt/mcp` |
| `BASE_PATH` | 留空 | 反代挂子路径时才填，须和 Nginx 一致 |
| `YLUNE_DOMAIN` | `ylune.example.com` | 可选。和证书一起填后走 HTTPS，控制台 / `mcp.json` 用这个域名 |
| `TLS_CERT_FILE` / `TLS_KEY_FILE` | `/data/certs/ylune/*.pem` | 可选。宿主机证书和私钥，只挂进 Nginx |
| `YLUNE_BIND` | `127.0.0.1` | 可选。启用 HTTPS 后建议绑本机，不对外明文开 3000 |

步骤、验收、备份、HTTP / HTTPS 反代见 [deploy/README.md](../deploy/README.md)。

### 2.4 常用环境变量（`.env.example`）


| 变量 | 示例 | 什么时候填 |
| --- | --- | --- |
| `PORT` | `3000` | 后端监听端口 |
| `NODE_ENV` | `development` / `production` | 生产用 `production` |
| `ADMIN_PASSWORD` | 强密码 | 首次创建管理员 |
| `BASE_PATH` | 留空 | 只有反代挂在子路径时才填，例如 `/ylune` |
| `DB_URL` | `postgresql://user:pass@host:5432/ylune` | **生产必填**。服务器 / 用户 / 组 / Key / 凭据都在这个库 |
| `YLUNE_MASTER_KEY` | `openssl rand -base64 32` | 凭据中心主密钥。不设时列表可读，写入失败 |
| `USE_DB` | `true` | 有 `DB_URL` 时自动开启；要强制文件模式才设 `false`（仅本地/测试） |
| `YLUNE_IMPORT_SETTINGS_FILE` | `data/mcp_settings.local.json` | 仅空库灌一次旧 JSON，成功后删文件、去掉变量 |
| `BETTER_AUTH_*` | 见第 10 节 | 第三方登录，用不到全部留注释 |


不要把填好的 `.env` 提交进仓库。

## 3. 登录与改密码

打开控制台 → 用户名、密码登录。**只有控制台账号能登录**；MCP 用户只拿 Access Key，不能进后台。内部入口，无公开注册。同一来源短时间失败太多次会被暂时拒绝。

![登录](images/login.jpg)

开发默认：`admin` / `admin123`。若提示默认密码不安全，点「前往修改」。


| 字段 | 怎么填 |
| --- | --- |
| 当前密码 | 现在正在用的密码 |
| 新密码 | 至少 8 位，且包含字母、数字、特殊字符 |
| 确认新密码 | 与新密码一致 |


改完用新密码重新登录。子用户没有「用户」菜单，只能改自己的密码。

侧栏大致是：仪表盘、服务器、提示词、资源、调试台（管理员和 Demo）、用户（管理员）、凭据中心（管理员）、设置、日志、活动、操作审计。Demo 账号能看见系统菜单，但项是灰色、点不了；直接访问这些地址会回到仪表盘。私有化默认不显示外部市场。授权在「用户」里做，没有单独的分组页。

## 4. 接入 DevOpsMCP（最常见的第一组服务）

先按 DevOpsMCP 仓库编出二进制。本机直连智能体：用它的 `deploy/pack-windows.cmd` 或 `pack-linux.sh`。月弦 Docker：用它的 `deploy/attach.sh` 自动注册，不必手填三个 STDIO 表单。

- **本机直跑月弦**：`command` 填宿主机绝对路径（Windows 带 `.exe`）。
- **月弦在 Docker、MCP 在同一台 Linux**：`command` 是容器内 `/opt/mcp/...`。见 [linux-deploy.md](linux-deploy.md)。

### 4.1 添加 Jenkins（STDIO）

**服务器 → 添加服务器**，类型选 **STDIO**。


| 字段 | 填什么 | 不要填 |
| --- | --- | --- |
| 服务器名称 | `jenkins`（字母数字、点、下划线、连字符，不能有空格） | `Jenkins 只读` 这种带空格的中文名 |
| 服务器注释 | 例如「Jenkins 只读排障」 | 真实 Token |
| 命令 | 月弦进程能看见的**绝对路径**。本机 Windows：打包目录里的 `jenkins-mcp-server.exe`。Docker：`/opt/mcp/jenkins-mcp-server` | 相对路径、只写文件名、或把宿主机 `/data/...` 填进容器 |
| 参数 | 通常留空（DevOpsMCP 的 Jenkins 不靠 args） | 不要把 Token 写进 args |
| 环境变量 `JENKINS_URL` | `http://你的Jenkins:端口` | 文档示例里的假地址当真的用 |
| 环境变量 `JENKINS_USER` | 只读用户名，例如 `mcp-user` | 超级管理员 |
| 环境变量 `JENKINS_API_TOKEN` | 该用户的 API Token；仓库配置里写成 `${JENKINS_API_TOKEN}`，值放系统环境变量 | 明文贴进 git |
| 环境变量 `JENKINS_MCP_TIMEOUT` | 可选，`90s` | |
| 可见性 | 选 **私有** 即可。MCP 能不能调看该用户的授权，不看这一项 | 指望「公开」让所有人调用 |
| 启用 | 打开 | |


保存后卡片应为已连接，并能列出工具（健康检查、Job、构建等）。失败先看卡片上的错误：路径不对、环境变量没展开、Jenkins 账号权限不够。

夜莺、PostgreSQL 同样：类型 STDIO，`command` 绝对路径，环境变量按 DevOpsMCP 对应 README 填（`N9E_BASE_URL` + `N9E_TOKEN`，或 `PG_TARGETS_FILE`）。PostgreSQL 的 targets 文件里不要写 `password` 字段。

### 4.2 智能体怎么连月弦

用户页创建用户后，左边选 **JSON** 或 **TOML**，右边 **复制内容**。预览会跟着格式变。

Cursor / WorkBuddy 用 JSON，形如：

```json
{
  "mcpServers": {
    "ylune-test": {
      "url": "http://<你打开控制台时的地址>:3000/mcp",
      "headers": {
        "Authorization": "Bearer <系统签发的用户 Key>"
      }
    }
  }
}
```

Cursor：写入 `~/.cursor/mcp.json` 或项目 `.cursor/mcp.json`。  
WorkBuddy：写入它的 MCP 配置或界面粘贴。

Codex 用 TOML。这是一段要**合并**进 `~/.codex/config.toml` 的表，不要整文件覆盖：

```toml
[mcp_servers.ylune-test]
url = "http://<你打开控制台时的地址>:3000/mcp"
http_headers = { Authorization = "Bearer <系统签发的用户 Key>" }
```

保存后在客户端里重载，确认该服务是绿的。

管理员自己调试：若勾了「允许 MCP」，可复制自己的 Access Key；仅后台管理员用调试台或设置里的系统 Key。普通同事只用自己的 Access Key。

## 5. 添加其它类型的服务器

**服务器 → 添加**。先选类型，再填该类型需要的字段。名称规则与上一节相同。

### 5.1 STDIO（本机进程）

适合 DevOpsMCP、`npx` / `uvx` 拉起的 MCP。


| 字段 | 填写 |
| --- | --- |
| 命令 | 可执行文件或 `npx` / `uvx` / `python` |
| 参数 | 空格或一行一个；例如 `npx` 的 `-y` `@某包` |
| 环境变量 | 点 + 添加键值。密钥用 `${NAME}` |
| 工作目录 | 可选。命令要相对某目录跑时才填 |
| 按需启动 | 不常用的服务打开：平时不占进程，第一次调工具再拉起 |
| 空闲关闭超时（毫秒） | 按需启动时有效。默认 `300000`（5 分钟无调用就退出） |
| 会话级客户端隔离 | Playwright 这类「有状态、不能多人共用一个浏览器」时打开。每多一个会话就多一条上游连接 |
| 连接超时 | 毫秒。上游慢再加大 |
| 最大总超时 | 毫秒。有进度通知的长任务用 |
| 收到进度通知时重置超时 | 默认开 |
| 连接健康检查 | 远端容易断时开；间隔默认 `60000` |


`npx` / `uvx` 要能在跑月弦的机器上找到。装包走设置里的 npm / PyPI 地址。

### 5.2 SSE / 流式 HTTP

上游已经是 HTTP MCP 时用。


| 字段 | 填写 |
| --- | --- |
| 服务器 URL | 完整 URL，例如 `https://example.com/sse` |
| HTTP 请求头 | 上游要的鉴权头。不要把值提交进 git |
| 健康检查 | 可选 |


不要把月弦自己的 `/mcp` 再填回自己（套娃）。

### 5.3 OpenAPI

把一份 OpenAPI 变成 MCP 工具。


| 字段 | 填写 |
| --- | --- |
| 输入模式 | **规范 URL** 或 **JSON 模式** |
| 规范 URL | 能拉到 `openapi.json` / `swagger.json` 的地址 |
| JSON 模式 | 整份规范粘贴进去 |
| 安全类型 | 无 / API 密钥 / HTTP / OAuth2 / OIDC；能检测则先检测再补凭据 |
| API 密钥：名称 | 头或参数名，例如 `X-API-Key` |
| API 密钥：位置 | 请求头 / 查询 / Cookie |
| API 密钥：值 | 密钥本身 |
| HTTP 方案 | Basic / Bearer / Digest |
| HTTP 凭据 | Basic 可填 `user:password`（会编码）或已是 Base64 |
| 规范文档需要单独的认证 | 只有「拉规范」和「调 API」不是同一套认证时打开 |
| 透传请求头 | 逗号分隔，例如 `Authorization, X-Request-Id` |
| Cookie 会话处理 | 上游靠登录 Cookie 时打开；按 MCP 会话隔离，不落盘 |


导入后看统计：工具太多会撑爆模型上下文。在用户授权里只勾需要的工具，或在服务器上关掉用不到的工具。

设置里的 **JSON 请求体大小限制**（例如 `1mb`）太小会导致大规范上传失败，可改成 `5mb`。

### 5.4 可见性（控制台，不是 MCP 调用权）


| 选项 | 含义（当前版本） |
| --- | --- |
| 私有 | 只有所有者和管理员能在控制台改这份配置 |
| 共享 | 再勾「共享给用户」：那些人可以在控制台看到，仍不能改配置 |
| 公开 | 已登录用户能在控制台看到 |


**MCP 调用不看这三项。** 普通用户必须在「用户」里勾到对应服务和工具，才能调 `/mcp`。

### 5.5 卡片上的操作

启用 / 禁用、重载、重新安装（清包缓存再拉依赖）、删除。有 OAuth 的服务可以「断开 OAuth」。单个工具、提示词、资源可以在卡片里关掉，不必删整台服务。

### 5.6 搜索、标签和工具变更

搜索框可以按服务器名、工具名或描述里的 `#标签` 过滤。描述写成 `Jenkins 只读 #ops #readonly` 后，上方会出现可点的标签。工具清单相对上次确认有增删时，页面顶部会提示；点确认后记住当前清单。

## 6. 用户（给谁用哪些工具）

**用户** 仅管理员可见。这里有两套身份：

| 入口 | 得到什么 | 能不能登录控制台 | 能不能调 `/mcp` |
| --- | --- | --- | --- |
| **创建 MCP 用户** | Access Key + `mcp.json` | 不能 | 能（还要勾工具） |
| **创建管理员** | 控制台密码 | 能 | 默认不能；勾「允许 MCP 调用」才签发 Access Key |
| **创建 Demo 账号** | 控制台密码 | 能（只读工作区） | 不能 |

智能体只连 **`/mcp` + 该用户的 Access Key**。控制台过期判断和 MCP Key 过期是分开的：Key 过期只让智能体 401，管理员仍能进后台。

### 6.1 添加 MCP 用户

| 字段 | 填写 |
| --- | --- |
| 用户名 | Access Key 的持有人名，例如 `test`。这个账号不能登录控制台 |
| 备注 | 可选，「值班测试」「某某用」 |
| Token 有效期 | 默认永久。也可选 1 / 7 / 30 / 90 天，或指定到期时间（必须晚于现在；选到过去的时间会弹出提示，不能创建或续期）。过期后 Key 不能调 `/mcp`，列表发灰，可续期或删除 |
| 可用的 MCP 与工具 | 先勾服务器，再勾这个用户能用的 tools。下面的**权限预览**会立刻算出这个 Key 会放出几个服务、几个工具。不勾则这个 Key 调 `/mcp` 没有任何工具 |

不要把值班同事勾成管理员。仅后台管理员默认没有 Access Key。兼 MCP 的管理员默认全部已启用服务，不受这份清单限制。可以细到某一个 tool，不必把整个 Jenkins 都给出去。

![用户权限：按人勾选服务器和具体工具](images/add-user.png)

创建成功后复制：

- **Key**：列表默认脱敏，点眼睛可看完整内容，也可以再复制。
- **接入配置**：左边选 JSON（Cursor / WorkBuddy）或 TOML（Codex），右边复制内容。`url` 是你当前打开控制台的公网地址 + `/mcp`，不要改成 `/mcp/组名`。TOML 只合并进 `~/.codex/config.toml`，不要整文件覆盖。

关闭对话框之后，用户列表每一行仍有格式切换和复制，编辑用户里也能再复制。不是只能复制一次。

公网用 `http://公网IP:3000` 打开控制台时，复制下来的配置应带这个 IP，而不是 `localhost`。HTTP 公网不是浏览器安全上下文，复制走了降级方案；若仍失败，可以全选页面上的预览手动复制。

### 6.2 给 `test` 开 Jenkins 的最小权限

1. 确认服务器 `jenkins` 已连接。
2. 用户页创建 `test`（或编辑已有用户）。
3. 勾 `jenkins`，工具先勾 `health_check`、`list_jobs`，确认能调后再加。
4. 复制接入配置交给对方。对方的 `/mcp` 只能看到这些工具。管理员连 `/mcp` 仍是全部。

### 6.3 编辑 / 续期 / 轮换 / 删除

可改备注、可用的 MCP 与工具、Token 有效期。用户页顶部的**到期中心**列出已过期和 7 天内到期的账号。

- **时钟**：续期。从现在起重新算 1 / 7 / 30 / 90 天，或改成永久 / 指定到期时间。指定到期时间必须晚于现在，选到过去的时间会弹出提示，不会保存。
- **钥匙**：轮换 Key。旧 Key 和已经发出去的 `mcp.json` 立刻失效，弹窗里再复制新 Key。
- 过期用户行会发灰，Key 不能再调 `/mcp`，但还可以续期、轮换或删除。
- 不能删除最后一个管理员。删除用户后，他的用户 Key 不能再调 MCP。

### 6.4 创建管理员

用户页另一个按钮。必填用户名和**控制台密码**。默认不签发 Access Key，列表也不给接入配置。需要这个人同时给智能体用时，勾「允许 MCP 调用」，有效期默认永久。

### 6.5 创建 Demo 账号

用户页第三个按钮。必填用户名和登录密码。这个账号：

- 能登录控制台，看到工作区：仪表盘、服务器、提示词、资源、调试台
- 侧栏 SYSTEM（用户、凭据中心、活动、操作审计、日志、设置）发灰，不能点；打开这些 URL 会回到仪表盘
- 工作区页面只能看：不能添加/编辑/开关/导入/调用工具；服务器配置里的命令、环境变量、地址不会返回
- 没有 Access Key，不能调 `/mcp`，也不能改成管理员

给客户或同事看一眼平台时用，不要把真实密钥页面开放给他们。

### 6.6 调试台

侧栏 **调试台** 给管理员，也给 Demo 只读看。管理员选一个用户后，工具列表按该用户的授权筛选；调用时带上**该用户的 Key**，用来验收「勾了哪些就能调哪些」。可用 inputSchema 生成的表单，也可以切回原始 JSON。选管理员账号则用当前登录会话。Demo 账号只能选服务器和工具看说明，不能调用。这里不是给智能体用的入口，智能体仍然只连 `/mcp`。

### 6.7 凭据中心

侧栏 **凭据中心** 只给管理员。一条凭据就是一个自定义键值包：地址、端口、Token / 密码都写在同一条里。绑定 MCP 可选，绑定不会改字段。凭据**不是**控制台密码，也**不是**智能体 Access Key。平台不按产品做固定表单，默认带出 `HOST` / `PORT` / `TOKEN`，键名可以改。

| 能做 | 不能做 |
| --- | --- |
| 直接创建凭据（不必先选 MCP），HOST / PORT / TOKEN 写在同一包 | 在列表页直接看到明文 |
| 创建 / 编辑时明文可见，点编辑会载入已保存的值 | 缺 `YLUNE_MASTER_KEY` 时写入（列表仍可读） |
| 可选地把凭据绑到 MCP，并用该凭据实测 `listTools` |  |
| 创建用户或给管理员开 MCP 时，选一条已绑定凭据 |  |

列表不展示明文。现有 Server 上的 `env` / `headers` 明文不会自动迁进凭据库。旧的 postgresql / token / basic 行仍能解密，会当成 `username`/`password`/`token` 这些键读出。

**和 MCP 关联：** 平台会扫每个已接入 MCP 的 `env`、headers、url、args、command 里的变量名和 `${VAR}`（忽略 `PATH` 这类系统变量）。凭据中心绑定区会标出「配置声明 / 尚未绑定 / 未声明变量」。配置里是空的（stdio 常把密钥只放凭据里）时扫不到，仍可绑定。停用的 MCP 也会出现，复制出的新环境可以先绑凭据再启用。凭据可以单独创建，绑定不改键值。绑上之后，创建用户或给管理员开 MCP 时才能给这个 MCP 选它。同一页可以对已绑凭据点「测试」（临时连一次并 `listTools`，不替换正在跑的进程）。用户授权里，凭据在该服务器下面勾选，和工具一样可以多选。勾上服务器时默认全选已绑凭据。调用时平台用这条凭据覆盖该 MCP 的环境变量。凭据测试或绑定成功后，服务器页按这次探测显示在线并缓存工具列表；没有凭据时 stdio 仍可能显示离线。

平台**不能**读二进制内部要哪些环境变量；只能看你写在 MCP 配置里的内容。从某个 MCP 创建凭据时，若扫到了变量名会带进表单，值仍要你填。

智能体参数里不要传密码。用户选了 MCP 凭据时，平台用这条凭据覆盖该 MCP 的环境变量，**不会**往工具参数里塞 `credentialLeaseId`（以免严格 schema 拒掉）。

用户页可搜索、按到期/未授权过滤，并把另一个用户的工具授权复制过来（不复制 Key）。多套环境（例如两套 Jenkins）请用服务器菜单 **复制为新服务器**：命令会复制，凭据绑定和用户授权不会。改成新名字后另建凭据、启用，再给用户勾上这个新 MCP。ENV 预检只显示 `${ENV}` 是否已设置，不回显值。工具清单变化改由服务端指纹计算，并列出受影响用户。管理操作（改授权、转 Key、改服务器/凭据/资源）记在侧栏 **操作审计**，与工具调用活动分开。导入备份前先看 +/~/- 预检，确认后才真正导入；导入只会新建，不会删已有项。

## 7. 仪表盘

管理员看到网关数字、智能体调用概况、已接入服务和控制台用户。顶部还有**故障提示**（没服务、没连上、用户没授权、Key 过期）和**到期中心**。用户列表上能直接看 Token 剩余时间、最近一次工具调用、账号创建时间；过期用户会发灰。下面（开了数据库活动日志）是近 7 天按工具 / 按用户的调用图，以及最近失败。管理员可点 **导出配置** 下载一份备份。管理员账号一般不调 MCP，所以仪表盘不展示「当前登录管理员」这类身份卡。

![仪表盘](images/dashboard.png)

普通用户登录后能看到自己的授权、智能体入口，以及自己的 Token 剩余时间、最近调用和创建时间。本页只看状态：不复制 mcp.json、不授权、不加服务器。授权和复制仍在「用户」，加服务在「服务器」。**Demo 账号**看到的是接入服务和工具数量，没有用户列表、调用统计、MCP 入口和 Token。

智能体默认只连 **`/mcp` + 自己的 Key**。不同 Token 返回的工具不一样，由该用户勾选的授权决定。

## 9. 设置 — 账户、外观、安全

**设置** 里分区保存。改完有的项会提示重启，按提示重启后端。

### 9.1 账户 / 外观

改自己的密码；切换语言和主题。与 MCP 授权无关。

### 9.2 安全配置（路由与鉴权）


| 开关 / 字段 | 建议 | 说明 |
| --- | --- | --- |
| 启用全局路由 | 开 | 允许连 `/mcp`、`/sse` 而不带组名 |
| 启用组名路由 | 开 | 允许 `/mcp/jenkins-readonly` 这种组名，而不只是 UUID |
| 启用 Bearer 认证 | **开** | MCP 端点要带 Key。关掉等于谁都能打网关（仅调试） |
| Bearer 认证密钥 | 一般留空 | 旧的单密钥；新部署用「密钥」列表 |
| Bearer 认证请求头名称 | `Authorization` | 仅当上游也要占用 `Authorization` 时改成 `X-MCP-Authorization` |
| 免登录开关 | **关** | 打开后控制台不登录也是 guest 管理员。不影响「MCP 是否要 Bearer」，但控制台等于没锁 |


### 9.3 密钥（系统级 / 用户级）

管理员可建两种 Key。


| 字段 | 系统级 | 用户级 |
| --- | --- | --- |
| 名称 | 例如 `ci-bot` | 例如 `test-cursor` |
| 密钥值 | 点「生成」或自己贴一串足够长的随机值 | 创建用户时系统已签发；也可再发 |
| 启用 | 打开才能用 | 同左 |
| 所属用户 | 无 | 必选，这个 Key 跟该用户勾选的工具走 |
| 访问范围 | `全部` / `指定分组` / `指定服务器` / `自定义` | 用户 Key 不按这套裁，跟该用户勾选的工具走 |


系统 Key 选「指定分组」时必须至少勾一个组；选「指定服务器」同理；「自定义」组和服务器至少填一类。

用户 Key 即使范围显示成「全部」，也**不能**越过成员名单去调未授权组。这是第一版的明确行为。

创建后立刻复制，之后列表脱敏。

## 10. 设置 — 安装、智能路由、压缩、OAuth、Better Auth

### 10.1 安装


| 字段 | 填写 |
| --- | --- |
| Python 包仓库地址 | 默认留空（PyPI）。内网镜像才填，例如 `https://pypi.example.com/simple` |
| NPM 仓库地址 | 默认留空。内网 npm 才填 |
| 基础地址 | 智能体和 OAuth 回调看到的公网根，例如 `https://ylune.example.com`。本机开发填 `http://127.0.0.1:3000` 或 `http://localhost:3000`。Docker 写了 `YLUNE_DOMAIN` 后，页面和 `mcp.json` 都以该域名为准，库里以前存的 IP 会被盖掉 |
| 名称分隔符 | 默认 `-`。工具对外名是 `服务器名-工具名`。已有客户端时不要随便改 |
| 清除包缓存 | 磁盘被 npm/uv 缓存撑满时用；下次启动会重新下载 |


基础地址填错：复制出来的 `mcp.json` 里的 `url` 会指向错误主机，客户端连不上。

### 10.2 智能路由（`$smart`）

不用就关。打开后需要：


| 字段 | 填写 |
| --- | --- |
| PostgreSQL 连接地址 | 必须带 pgvector，例如 `postgresql://ylune:口令@127.0.0.1:5432/ylune` |
| 嵌入提供方 | OpenAI / OpenRouter / SiliconFlow / Gemini / 自定义 |
| OpenAI 兼容基础地址 | 选预设会带出；自定义再改 |
| LLM 提供商 API 密钥 | 云端必填；本地模型可填任意占位通过校验 |
| 嵌入模型名称 | 与提供方一致，例如 `text-embedding-3-small` |
| 基础节流延迟 | 一般留空（0，系统自己退避） |
| 嵌入维度 | 一般留空 |
| 渐进式披露 | 工具特别多时打开：先搜名字，再 `describe_tool` |
| 最大嵌入 Token 数 | 一般留空 |


没配库就打开会保存失败。`$smart` 对普通用户仍然只在其所属组合集里搜。

### 10.3 工具结果压缩


| 字段 | 填写 |
| --- | --- |
| 启用压缩 | 控制台日志、超长 JSON 把上下文打爆时再开 |
| 策略 | `auto`：按 JSON / 日志 / 搜索 / diff / 文本处理 |
| 最小 Token 数 | 默认约 `2000`，小于此不压 |
| 输出 Token 预算 | 默认约 `1200`，压完一块的目标上限 |


下次工具调用生效，不用重启。

### 10.4 月弦作为 OAuth 授权服务器

只有外部客户端要向月弦要码、换 Token 时才开。


| 字段 | 建议 |
| --- | --- |
| 启用 OAuth 服务器 | 默认关 |
| 需要客户端密钥 | 机密客户端开；纯 PKCE 公共客户端可关 |
| 要求 state | 建议开 |
| 访问令牌有效期（秒） | `3600` |
| 刷新令牌有效期（秒） | `1209600`（14 天） |
| 授权码有效期（秒） | `300` |
| 允许的作用域 | `read, write`（逗号分隔，会显示在授权页） |
| 动态客户端注册 | 默认关；打开等于谁都能注册客户端 |
| 注册需要认证 | 若打开动态注册，建议再打开这项 |


### 10.5 Better Auth（GitHub / Google / 本机 OIDC）

控制台第三方登录。需要 `DB_URL`，会话不支持纯文件模式。客户端 ID / Secret **只走环境变量**，不要写进设置 JSON。


| 字段 | 填写 |
| --- | --- |
| 启用 Better Auth | 环境变量齐了再开 |
| 基础地址 | 公网 URL；留空则用「安装 → 基础地址」。`BETTER_AUTH_URL` 优先 |
| 认证基础路径 | 默认 `/api/auth/better` |
| 受信任来源 | 控制台若从另一个源打开，逗号分隔 origin |
| Google / GitHub / OIDC 开关 | 只控制登录页显示；对应 `*_CLIENT_ID` / `*_CLIENT_SECRET` 必须已在环境里 |
| OIDC 提供方 ID | 例如 `local-oidc` |
| OIDC Discovery URL | `https://idp.example.com/.well-known/openid-configuration` |
| OIDC Scopes | 默认 `openid,profile,email` |
| OIDC Prompt | 可选 `login` 或 `consent` |
| 启用 PKCE | 建议开 |


第三方登录成功只会映射或创建一个**非管理员**本地用户。管理员必须本来就是本地 `isAdmin`。

## 17. 常见问题

**`test` 连上了但一个工具都没有。**  
还没在用户页给 `test` 勾服务器和工具。管理员自己不会有这个问题。

**勾了仍没有 Jenkins。**  
用户授权里是否勾了 `jenkins`、服务是否已连接、用户 Key 是否属于这个用户、客户端 `url` 是否指向当前这台月弦（不要用 `/mcp/组名`，也不要 `localhost` 当公网部署）。

**控制台能看到服务，MCP 调不了。**  
可见性只影响控制台。调用看该用户勾选的 MCP 和工具。

**连上的是旧工具列表。**  
是否另有一份旧 `tsx` 占着 3000；改完授权后在客户端里重载 MCP。

**智能路由 500 / 空结果。**  
库地址、pgvector、嵌入 Key 是否齐；普通用户是否根本没有勾任何工具。

**复制接入配置点了没反应。**  
公网 HTTP 不是安全上下文。已做降级复制；仍失败时全选页面上的预览手动复制。用户列表随时可以再点复制。JSON 给 Cursor / WorkBuddy，TOML 给 Codex。

**OpenAPI 上传失败。**  
把「JSON 请求体大小限制」加大，或改用规范 URL。

字段以当前控制台文案为准；行为变更后会改这一页和根目录 README。
